# فایل پرونده در وب و اندروید

وضعیت ۸ نوامبر ۲۰۲۶: ذخیرهٔ JSON پرونده در افزونهٔ اندروید پیاده و Java آن کامپایل شد. آزمون فایل‌سیستم روی گوشی یا شبیه‌ساز انجام نشده است. این تحویل، پذیرش کامل Android، PDF/HTML آزمایشگاهی یا نصب نسخهٔ تازه نیست.

## یافته و تغییر

پیش از این، NativeExport فقط HTML گفت‌وگو را ذخیره/چاپ/اشتراک‌گذاری می‌کرد. ذخیرهٔ پروندهٔ آزمایشگاه مستقیماً با Blob و anchor انجام می‌شد؛ این مسیر برای WebView اندروید تأیید نشده بود. اکنون دکمه‌های «ذخیرهٔ فایل پرونده» که به مالک همان پرونده وصل‌اند، از `save-project-file.ts` عبور می‌کنند.

- در مرورگر، JSON با همان ساختار قبلی برای دانلود آماده می‌شود. این نتیجه «آغاز دانلود» است، نه تأیید ذخیره روی دیسک.
- در Android پشتیبانی‌شده، `getDocumentCapabilities` باید protocol=1 و saveJson=true بدهد. سپس `saveJson` انتخابگر سیستم را با ACTION_CREATE_DOCUMENT و MIME application/json باز می‌کند؛ کاربر محل و نام فایل را انتخاب می‌کند.
- موفقیت تنها پس از نوشتن UTF-8، flush و بستن stream گزارش می‌شود. انصراف نتیجهٔ جدا دارد و به موفقیت یا خطا تبدیل نمی‌شود. خطا، پیش‌نویس را پاک نمی‌کند.
- در بستهٔ قدیمی یا افزونهٔ ناموجود، پیام روشنِ نیاز به نسخهٔ وب/بستهٔ تازه نمایش داده می‌شود. fallback خاموش و بی‌خبر به دانلود WebView وجود ندارد.

فقط URI نوع content که از نتیجهٔ انتخابگر آمده، مقصد نوشتن است. مسیر فایل یا URL دلخواه از JavaScript پذیرفته نمی‌شود. نام پیشنهادی محدود و دارای پسوند json است؛ ورودی باید JSON object و حداکثر ۱۲ MiB UTF-8 باشد. انتخابگر، مجوز همان مقصد را از کاربر می‌گیرد و permission عمومی تازه‌ای برای storage اضافه نشده است. این الگو مطابق [Storage Access Framework اندروید](https://developer.android.com/training/data-storage/shared/documents-files) و callbackهای [Capacitor](https://capacitorjs.com/docs/plugins/android) است.

هنگام انتظار، نوار فایل در وضعیت busy است و save دوبارهٔ هم‌زمان در مالک پرونده با ref جلوگیری می‌شود؛ افزونه نیز درخواست هم‌زمان را رد می‌کند. قرارداد callback فرم‌ها async شده است. فرم محلول، Promise را به‌جای موفقیت فوری در نظر نمی‌گیرد و انصراف را خطا نشان نمی‌دهد. schema JSON، معادله‌ها و داده‌های علمی تغییر نکرده‌اند؛ snapshot ذخیره، داده‌های زمان زدن ذخیره است.

ثبت NativeExport در `native-export.ts` مشترک شد تا صفحهٔ خروجی گفت‌وگو و ذخیرهٔ پرونده، افزونه را دوبار register نکنند. روش‌های HTML قبلی حفظ شدند و این تحویل مسیر آن‌ها را به JSON تبدیل نمی‌کند.

## آزمون و کامپایل

شش آزمون واسط، شاخهٔ وب، JSON فارسی، موفقیت native با URI تأییدشده، انصراف، افزونهٔ قدیمی، خطای نوشتن، ورودی/نام نامعتبر و سقف UTF-8 را بررسی می‌کنند. چهار آزمون مالک واقعی workspace، انتظار نتیجه، جلوگیری از کلیک تکراری، حفظ شناسنامه پس از انصراف/خطا و تفاوت پیام وب/native را می‌آزمایند. پاسخ native در این آزمون‌ها mock است.

کل frontend: ۸۱ فایل و ۵۶۵ آزمون موفق. پس از یکپارچه‌کردن register افزونه، ده آزمون مرتبط دوباره موفق شدند. TypeScript، lint فایل‌های تغییرکرده و build تولید با ۴۸ مسیر موفق‌اند؛ warning ثبت تکراری افزونه در build نهایی برطرف شد.

کامپایل واقعی `:app:compileDebugJavaWithJavac` با JDK 21.0.11+10 و Gradle 8.14.3 موفق شد: ۷۴ task، ۲۲ اجرا و ۵۲ up-to-date. اجرای اولیهٔ محدودشده در دریافت Gradle خطای permission داشت؛ با دسترسی تأییدشده، wrapper اجرا شد. حالت offline وابستگی‌های AGP 8.12.3 و Google Services 4.4.3 را نداشت؛ دریافت آنلاین و سپس کامپایل موفق انجام شدند. warningهای flatDir، ناهم‌زمانی نسخهٔ SDK XML ابزارها و deprecation Gradle باقی‌اند؛ خطای کامپایل نبودند. نسخهٔ release یا امضاشده ساخته/نصب/منتشر نشده است.

## رفت‌وبرگشت واقعی وب

در اجرای جداگانهٔ build تولید روی localhost:3115، پرونده‌ای کاملاً فرضی با شناسهٔ `DEMO-WEB-SAVE-45` ذخیره شد. فایل دانلودشده روی دیسک بررسی شد. پس از reload، همان فایل از انتخابگر باز و پیش‌نمایش آن صریحاً اعمال شد؛ عنوان و شناسه حفظ بودند و پیام نیاز به محاسبهٔ مجدد نمایش داده شد.

- شاهد JSON: `output/stage9-project-save-roundtrip.json`
- تصویر: `docs/stage9-project-save-roundtrip-fa.png`

انتخاب فایل در ابزار مرورگر تأخیر طولانی داشت، اما پیش‌نمایش و اعمال نهایی موفق بودند. نتیجهٔ وب، تأیید انتخابگر یا فایل‌سیستم Android نیست. تب و فرایند موقت وب پس از بررسی بسته شدند.

## پذیرش دستگاه و انتشار باقی‌مانده

Config اندروید `server.url` راه‌دور دارد. بخش وب از سرور خوانده می‌شود، اما روش Java تازه با انتشار وب وارد بستهٔ نصب‌شده نمی‌شود؛ برای این قابلیت APK تازه لازم است. نسخهٔ نصب‌شده و versionCode آن بررسی نشده و versionCode مخزن برای انتشار بعدی در این تحویل تغییر نکرده است.

روی گوشی/شبیه‌ساز باید ذخیره، انصراف، provider ناموجود/خطای نوشتن، فایل فارسی نزدیک سقف، دوباره‌خواندن JSON از input موجود، چرخش/مرگ فرایند و فضای کم بررسی شوند. فایل ناقص در خطای provider به‌صورت موفق معرفی نمی‌شود؛ پاک‌شدن خودکار فایل ناقص تضمین نشده است. نگهداری داده بعد از بسته‌شدن فرایند همچنان به فایل ذخیره‌شده نیاز دارد.

دانلود مستقل گزارش‌های PDF/HTML، JSON منابع ChEBI/NIOSH/CompTox و «دریافت پروندهٔ GUM اصلی» هنوز مسیرهای جدا دارند و در پذیرش native این تحویل نیستند. اشتراک‌گذاری یا ارسال فایل به سرویس بیرونی خودکار نشده است. مرحلهٔ ۹ همچنان باز است.


ادامهٔ همان روز: مسیر PDFهای آزمایشگاهی منتخب نیز پیاده/کامپایل و دانلود وب آن بررسی شد؛ ANDROID_LAB_PDF_REVIEW.md دامنه را مشخص می‌کند. بندهای بازِ PDF در این سند وضعیت پیش از آن تحویل را شرح می‌دهند. آزمون گوشی/APK و مسیرهای مستقل HTML/JSON مرجع/GUM اصلی همچنان بازند.
