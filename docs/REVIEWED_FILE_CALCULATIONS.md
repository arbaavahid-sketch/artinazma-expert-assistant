# Reviewed file calculations

The file analysis page and assistant analysis messages link to `/laboratory-imports?analysis=<question_id>`. The backend resolves only the signed-in owner's stored analysis source. The workspace also links to direct file import. Existing analysis text is interpretation; it is not used as a numerical table.

CSV (UTF-8) and XLSX are parsed directly. PDF and images are transcribed through the configured Responses API with a strict table schema, `store: false`. Transcription is explicitly unverified. A failed/incomplete transcription produces an empty preview with manual tab-separated entry, never invented numerical cells. Limits: 10 MiB source, 20 PDF pages, 8 workbook sheets / extracted tables, 1000 rows per table, 24 columns. Oversized tables fail instead of silently truncating rows. Legacy XLS should first be saved as XLSX or UTF-8 CSV.

The user selects a source table, rows, edits, column mappings, actual units, decimal convention, assumptions and a review note. A final checkbox authorizes calculation. Any input edit clears the previous result and review confirmation. Invalid, unreadable, ND and inequality cells fail with a row/column location; exclusion must be explicit. Supported calculations are sample statistics, unweighted OLS, registered nominal equations, and independent linear GUM budgets with one uncertainty distribution for the selected rows. Mixed distributions, correlations and complete method validation remain in the existing full forms. SEM requires confirmed independence; RSD additionally requires a ratio scale. OLS excludes x uncertainty.

Each confirmation creates an immutable new database record with source SHA-256, original row identities, before/after edits, reviewed selection and note, timestamp, numerical engine output and revision. Private source files reside in `backend/storage/lab_imports/`, outside the public uploads mount. Both this folder and the `laboratory_imports` database table must be included in server backups. Records are retained until an operator's explicit retention/deletion process; there is currently no self-service deletion or imports-history screen. These records are separate from the admin questions list. General laboratory chat remains temporary and ordinary calculator runs are not automatically archived by this feature.

All import, source, confirmation and recalculation endpoints require an approved customer. Ownership is enforced again for every lookup and for analysis-to-import conversion. No arbitrary URL download is supported. Recalculation and the chat `recalculate_import` tool load the immutable, owned server selection and re-run the numerical engine. They never accept a saved client result as authoritative. Project JSON contains a historical copy of the reviewed data and result; opening it cannot establish source ownership or numerical verification. A compact source identity is sent in chat context to avoid embedding large tables. Artin must use the server tool before interpreting imported results.

Results can be transferred to a dedicated `data-import` laboratory project or to Artin's laboratory conversation. Workspace replacement always requires the visible project preview. The project retains the reviewed source/result when exported as JSON; HTML reports distinguish historical output from a fresh server recalculation.

App access policy: native Capacitor, Electron and home-screen standalone clients show sign-in/register instead of the website trial contact gate. The server rejects unauthenticated `client_surface: app` chat requests without consuming website allowance. Surface detection changes presentation and can only restrict access; it is not an authentication credential. Regular browser guests retain the existing website trial. Sign-in/register remain accessible in the ordinary chat header.

Laboratory controls are contextual: the ordinary assistant has no extra laboratory toolbar. A handoff from the workspace/file calculation page opens its laboratory conversation via `?lab=1`. JSON attachment is inside that conversation; data files have a separate explicit import action. The close button remains sticky within the scrolling dialog. Opening a workspace JSON file shows a modal preview at the current scroll position and focuses the loaded project after confirmation.

Validation includes offline backend ownership, parsing, unit conversion, correction audit, extraction-failure and numerical tests; frontend review/invalidation, handoff, project roundtrip and app access tests; production build; browser checks of the project preview and mobile sticky close. Live PDF/image extraction depends on the configured provider and must be checked with a non-sensitive representative source after deployment.

## Shared laboratory reference retrieval

Ordinary chat and laboratory chat call the same `library_chat_context` service. Explicit formulas, CAS numbers, CIDs and saved compound names resolve through the same PubChem gateway and imported identity index as the material library. Formula matches remain candidates when more than one CID is returned; list order never selects a compound. Failed live retrieval is labelled as a catalogue snapshot and does not fabricate physical properties. Material-card questions send the selected CID separately from user prose. The UI returns exact-CID links and source selectors; ordinary assistant chat has no permanent laboratory attachment toolbar.

Elements/isotopes use a deterministic exported mirror of the existing versioned frontend snapshot (`backend/eval/export_lab_reference_context.py`); rerun that exporter whenever the UI source snapshot changes. Specific isotope queries retain source mass, uncertainty and half-life units. NIOSH exposure questions use the same reviewed snapshot even without an English NIOSH keyword when one exact CAS or snapshot name resolves. US reference status and separate REL/PEL/IDLH meanings are preserved. Explicit ChEBI identifiers use the existing service. CompTox remains an explicit-DTXSID identity adapter and honestly reports missing API configuration; no toxicity or model outputs are invented. Private bottle/certificate metadata is included only in an explicitly attached laboratory project, with binary certificate attachments stripped. Public compound identity never establishes batch purity.

Returned reference cards are retained in normal customer chat session metadata and the admin question metadata. Reference-sensitive answers bypass the anonymous text-only response cache. Clicking a material reference inside the workspace changes the reference view without unloading an unsaved project. Initial external links open the selected compound or element, and explicit ChEBI/NIOSH/CompTox references select their own section. Live smoke validation for the user-reported CID 198139 successfully retrieved the PubChem identity and available reference annotations; this is separate from laboratory validation or product/SDS verification.

The method list and material directory start collapsed. Method search/filtering stays visible and opens its result list automatically. Users can expand/collapse either list explicitly. The collapsed compound directory does not fetch or translate hidden catalogue pages.
