# صورت‌وضعیت فنی پروژه — ArtinAzma Expert Assistant
**تاریخ:** ۲۰ خرداد ۱۴۰۵ (2026-06-10) · **نوع:** ممیزی جامع فنی · **دامنه:** کل کدبیس (backend + frontend + infra)

---

## ۰) خلاصه‌ی مدیریتی

پروژه در وضعیت **بسیار خوب و آماده‌ی production** قرار دارد. این یک پروژه‌ی بالغ مهندسی‌شده است، نه یک نمونه‌ی اولیه. زیرساخت، امنیت، مانیتورینگ و CI در سطحی هستند که در بسیاری از شرکت‌های متوسط هم دیده نمی‌شود.

**نمره‌ی کلی: A− (۹۰/۱۰۰)**

نقاط قوت اصلی: امنیت چندلایه، استک استقرار کامل (Docker + Nginx/TLS + مانیتورینگ + بکاپ خودکار)، کیفیت بالای پاسخ AI (۹۳/۱۰۰ با توهم صفر در eval)، و خط‌لوله‌ی CI کامل.

سه ریسک/بدهی اصلی که باید پایش شوند: (۱) کش و rate-limit **درون‌حافظه‌ای** هستند در حالی که Redis در stack موجود ولی **بلااستفاده** است → مانع مقیاس افقی، (۲) چند فایل غول‌پیکر (۱۰۰۰ تا ۱۶۵۰ خط)، (۳) پوشش eval کیفیت AI نازک است (فقط ۳ از ۱۶ کیس قضاوت شده).

## ۱) معماری — نمره: A−

ساختار دولایه‌ی تمیز:
- **بک‌اند (FastAPI):** خط‌لوله‌ی لایه‌ای — تشخیص intent → بازیابی دانش دوسطحی (جستجوی محلی سریع + جستجوی برداری AI) → جستجوی منابع سایت → پاسخ AI (Responses API با web_search) → ذخیره‌سازی. لایه‌ی داده با الگوی repository و آداپتور دوگانه‌ی SQLite/PostgreSQL.
- **فرانت‌اند (Next.js 16 / React 19):** App Router، RTL کامل، dark mode، طراحی مبتنی بر design token، PWA با حالت offline.

**نقطه‌ی قوت:** تفکیک مسئولیت‌ها خوب است؛ سرویس‌ها (intent، knowledge، ai، site_resource، comparison_table و...) ماژولار و قابل‌تست‌اند.

**بدهی:** چند فایل بیش‌ازحد بزرگ شده‌اند (بخش ۵).

---

## ۲) امنیت — نمره: A

این قوی‌ترین بخش پروژه است:
- **CSRF:** میدل‌ور اختصاصی با توکن مبتنی بر secret، کوکی `artin_csrf` و اعتبارسنجی هدر روی همه‌ی متدهای تغییردهنده (POST/PUT/PATCH/DELETE)، با لیست استثناهای کنترل‌شده.
- **احراز هویت:** JWT (کوکی `artin_jwt`) + هش `bcrypt` برای رمزها. هشدار صریح اگر `JWT_SECRET` تنظیم نشده باشد.
- **Rate limiting + ضدِ brute-force:** `slowapi` (۲۰ req/min روی `/chat`) به‌علاوه‌ی یک `_SmartRateLimiter` اختصاصی.
- **مدیریت اسرار:** `.env`، `google-service-account.json` و `*.db` همگی به‌درستی در `.gitignore` و **ردیابی‌نشده** در گیت.
- **CI gating امنیتی:** اسکن secret، `pip-audit` و `npm-audit` که build را روی آسیب‌پذیری‌های allow-list‌نشده می‌شکنند.

**توصیه (جزئی):** مطمئن شو در production متغیرهای `CSRF_SECRET` و `JWT_SECRET` صریحاً ست شده‌اند (وگرنه در هر ری‌استارت کلید تصادفی تولید می‌شود و توکن‌ها بی‌اعتبار).

## ۳) وابستگی‌ها — نمره: B+

نسخه‌ها به‌روزند: `fastapi 0.136`, `openai 2.33`, `pydantic 2.13`, `next ^16.2`, `react 19.2`. CI آسیب‌پذیری‌ها را gating می‌کند.

**موارد قابل‌رفع:**
- **ناهماهنگی نسخه‌ی پایتون:** `Dockerfile` از `python:3.12-slim` ولی CI از `python 3.11` استفاده می‌کند. بهتر است یکسان شوند (ترجیحاً ۳.۱۲ در هر دو) تا «روی سیستم من کار می‌کرد» پیش نیاید.
- **`lucide-react ^1.14.0`** در package.json مشکوک به‌نظر می‌رسد (نسخه‌های رایج این پکیج `0.x` هستند). ارزش یک‌بار بررسی دارد که نسخه‌ی درست نصب شده باشد.

- **بک‌اند:** ۱۴۸ تابع تست (intent، chat logic، repositories، services، sessions).
- **فرانت‌اند:** ۱۰ فایل تست (unit با Vitest) + e2e با Playwright.
- **CI (`ci.yml`):** کامل — secret scan، ruff، syntax check، pytest، pip-audit، سپس tsc، eslint، vitest، playwright، production build، npm-audit، و در نهایت docker compose smoke. این یک خط‌لوله‌ی نمونه است.

**بدهی:** پوشش تست فرانت‌اند نسبت به حجم (۲۱هزار خط) سبک است؛ صفحات بزرگ مثل `assistant/page.tsx` منطق چندانی تست‌شده ندارند.

## ۶) کیفیت AI / RAG — نمره: A

- **eval کیفیت پاسخ:** میانگین **۹۳.۶۷/۱۰۰**، groundedness/citation/relevance همگی ۵.۰، **نرخ توهم صفر**.
- **طبقه‌بندی intent:** ۱۶ از ۱۶ پاس.
- مدل: `gpt-5.1` با OpenAI Responses API و ابزار `web_search_preview`؛ موتور کیفیتِ پاسخ (answer_quality_service) با قواعد per-intent پیچیده.
- لینک‌دهی محصول زنده (با عکس) و کش پاسخ از قبل موجودند.

**بدهی:** eval کیفیت فقط روی **۳ از ۱۶ کیس** اجرا شده (به‌دلیل هزینه/زمان). برای اطمینان از regression، ارزش دارد همه‌ی ۱۶ کیس به‌صورت دوره‌ای judged شوند. (باگ «جدول مقایسه» که این سشن یافت و رفع شد، نمونه‌ای از چیزی است که فقط با eval پیدا می‌شود.)

## ۷) عملکرد و مقیاس‌پذیری — نمره: B  ⚠️ مهم‌ترین یافته

- **کش پاسخ:** یک `dict` درون‌حافظه‌ای با TTL و eviction از نوع LRU.
- **Rate limiting:** درون‌حافظه‌ای (`_SmartRateLimiter` + slowapi memory).
- **Redis** در `docker-compose` provision شده ولی **در کد اپ استفاده نمی‌شود**.
- بک‌اند با **یک worker** اجرا می‌شود (`uvicorn` بدون `--workers`).

**نتیجه:** تا وقتی یک instance/worker داری، همه‌چیز درست کار می‌کند. اما به‌محض **مقیاس افقی** (چند replica یا چند worker)، کش و rate-limit درون‌حافظه‌ای ناسازگار می‌شوند (هر worker کش و شمارنده‌ی جدا دارد). راه‌حلِ آماده همان Redisِ بلااستفاده است.

**توصیه:** وقتی به مقیاس رسیدی، کش پاسخ و ذخیره‌ی rate-limit را به Redis منتقل کن. تا آن زمان، اولویت پایین.

## ۸) دیتابیس و داده — نمره: A−

- آداپتور دوگانه: **SQLite** (dev) / **PostgreSQL** (prod، با `DATABASE_URL`) پشت یک API سازگار با sqlite3.
- مهاجرت‌های schema با **Alembic** (۵ migration).
- جستجوی برداری: JSON store (`knowledge_vectors.json`, ~۵.۸MB) یا **Qdrant** (با `QDRANT_URL`).

**توجه:** لود کامل `knowledge_vectors.json` در حافظه با رشد دانش گلوگاه می‌شود؛ Qdrant آماده‌ی فعال‌سازی در production است.

## ۹) استقرار و زیرساخت — نمره: A

`docker-compose` یک استک production کامل است: **postgres 16، redis 7، qdrant، backend، frontend، nginx (TLS با certbot)، prometheus، grafana، و بکاپ خودکار postgres** — همگی با `healthcheck` و volumeهای named. این سطح از زیرساخت برای یک پروژه در این اندازه، استثنایی است.

---

## ۱۰) مشاهده‌پذیری (Observability) — نمره: A

- **Sentry** برای ردیابی خطا (در `main.py` و `routes/admin.py`).
- **prometheus-fastapi-instrumentator** برای متریک‌ها + **Grafana** برای داشبورد.
- **لاگینگ JSON ساخت‌یافته** (`_JSONFormatter`).

## ۱۱) فرانت‌اند — نمره: A−

Next.js 16 + React 19، RTL کامل با فونت فارسی self-hosted، dark mode با design token، PWA با صفحه‌ی offline، پنل ادمین کامل، چت بلادرنگ (WebSocket: `ws_chat.py`). a11y این سشن بهبود یافت. بدهی همان فایل‌های بزرگ بخش ۵ است.

## ۱۳) توصیه‌های اولویت‌دار (نقشه‌ی ۹۰ روزه)

**فوری (این هفته):**
1. تأیید ست‌بودن `JWT_SECRET` و `CSRF_SECRET` در محیط production.
2. یکسان‌سازی نسخه‌ی پایتون (۳.۱۲ در CI و Docker).
3. commit و ship کارهای سشن جاری.

**کوتاه‌مدت (یک ماه):**
4. اجرای کامل eval کیفیت روی هر ۱۶ کیس و ثبت baseline؛ افزودن به CI به‌صورت دوره‌ای.
5. شروع شکستن بزرگ‌ترین فایل‌ها (admin/knowledge، admin/dashboard) — هر بار یکی.

**میان‌مدت (سه ماه، فقط اگر به مقیاس رسیدی):**
6. انتقال کش پاسخ و rate-limit به Redis.
7. فعال‌سازی Qdrant در production به‌جای JSON store.
8. افزایش پوشش تست فرانت‌اند روی منطق چت.
