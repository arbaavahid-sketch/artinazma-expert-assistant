# بازبینی ذخیرهٔ گواهی پیوست در Android

۸ نوامبر ۲۰۲۶. دامنه: دریافت نسخهٔ محلی گواهی پیوست PDF/PNG/JPEG؛ محتوای گواهی و منطق علمی تغییر نکرده‌اند.

saveCertificateFile پیش از ذخیره، همان اعتبارسنجی پیوست را اجرا می‌کند: MIME منتخب، امضای ابتدایی، base64، نام تا ۲۰۰ نویسه بدون مسیر/کاراکتر کنترلی و سقف ۱MiB. نام اصلی، از جمله فارسی و فاصله، و بایت‌های اصلی حفظ می‌شوند. تشخیص امضا فقط کنترل نوع فایل است و صحت محتوای گواهی را اثبات نمی‌کند.

Android قابلیت مستقل saveCertificate در protocol1 دارد. انتخاب مقصد با ACTION_CREATE_DOCUMENT و MIME اصلی است؛ کنترل نام، نوع، اندازه و امضا در Java نیز اجرا می‌شود. نوشتن باینری از base64 با callback مشترک، خارج از UI thread انجام می‌شود. موفقیت پس از flush و بستن stream و فقط برای content URI اعلام می‌شود. قفل native با سایر ذخیره‌ها مشترک است. انصراف، نبود قابلیت در بستهٔ قدیمی و خطای provider پیام جدا دارند. fallback بی‌صدای WebView وجود ندارد.

رابط هنگام انتظار ذخیره، دریافت تکراری و تغییر پیوست را غیرفعال می‌کند. انصراف/خطا پیوست را حذف نمی‌کند. پیام ذخیره متعلق به همان پیوست است؛ نام/دادهٔ خطای خام نمایش داده نمی‌شود. وب همچنان فایل اصلی را با Blob دریافت می‌کند؛ لینک حذف و URL پس از ۳۰ ثانیه آزاد می‌شود. شروع دانلود وب پیام تأیید نوشتن روی دیسک نیست. برای این تغییر مرورگر واقعی یا گوشی آزموده نشد.

پذیرش خودکار: ۸ آزمون جدید برای سه MIME، بایت‌های غیرمتنی، نام فارسی، انصراف، کلیک تکراری، نسخهٔ قدیمی، مقصد نامعتبر، خطای نوشتن و اعتبارسنجی فایل موفق‌اند. همراه با آزمون‌های موجود پیوست و JSON/PDF/HTML مجموعاً ۲۷ آزمون منتخب موفق‌اند. پس از اصلاح نوع دو fixture آزمون، build با ۴۸ مسیر، TypeScript و lint موفق شدند. کل مجموعه در این نوبت دوباره اجرا نشد. compileDebugJavaWithJavac با JDK21 موفق: ۷۴ task، یک اجرا و ۷۳ up-to-date؛ هشدارهای قبلی ابزار ساخت پابرجاست.

APK تازه ساخته/نصب/منتشر نشده است. پذیرش روی گوشی باید ذخیره و بازخوانی هر سه نوع، تطبیق بایت‌ها، نام فارسی، providerهای مختلف، انصراف، خطای فضای ذخیره، بازگشت از پس‌زمینه و مرگ فرایند را پوشش دهد. provider ممکن است برای تکرار نام یا پسوند، نام پیشنهادی را تغییر دهد؛ حفظ نام در درخواست برنامه به معنی تضمین نام نهایی توسط provider نیست. داده در پروندهٔ JSON طبق مسیر قبلی حفظ می‌شود.


ادامهٔ ۸ نوامبر: بستهٔ جداگانهٔ filesQa روی POCO X6 Pro/Android16 نصب شد. ذخیرهٔ واقعی PDF/PNG/JPEG با نام فارسی و تطبیق SHA-256 هر سه، و انصراف همراه حفظ پیوست پذیرفته شدند. دامنه و شواهد در ANDROID_APK_FILES_ACCEPTANCE.md هستند؛ providerهای دیگر و شرایط خطا هنوز بازند. بندهای «نصب نشده» در بالا وضعیت پیش از این ادامه را شرح می‌دهند.
