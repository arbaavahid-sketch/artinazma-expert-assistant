# ارزیابی سبک دستیار آرتین (Eval Harness)

یک «خط‌کش» برای اندازه‌گیری کیفیت پاسخ‌های دستیار. چیزی به هوش اپ اضافه نمی‌کند؛
به تو عددی می‌دهد که تا حالا نداشتی تا **قبل و بعد از هر تغییرِ پرامپت/مدل/دانش**
بفهمی بهتر شد یا بدتر.

## فلسفه

- `eval_questions.json` مجموعه‌ای از **نمونه‌های نماینده** است (نه کل فضای سؤال‌ها).
  مثل فشارخون و تب برای دکتر: نماینده‌ی سلامت کل سیستم‌اند.
- برای هر سؤال، هارنس دقیقاً مثل یک کاربر واقعی به `/chat` می‌زند (کل پایپ‌لاین:
  intent → بازیابی → پاسخ AI → وب‌سرچ)، بعد پاسخ را با **داور LLM** نمره می‌دهد.
- داور **فقط** بر اساس معیارهای همان فایل قضاوت می‌کند و از دانش بیرونی شرط جدید نمی‌سازد.

## اجرا

```powershell
cd backend
.\venv\Scripts\Activate.ps1

# بک‌اند باید بالا باشد (یک ترمینال جدا)
uvicorn main:app --port 8000

# اجرای ارزیابی (ترمینال دیگر)
python -m eval.run_eval
```

### پرچم‌های مفید

| پرچم | کار |
|------|-----|
| `--base-url URL` | ارزیابی روی نسخه‌ی دیگر (مثلاً `https://assistant.artinazma.net`) |
| `--only q01_astm_d445,q11_...` | فقط چند سؤال خاص |
| `--limit N` | فقط N سؤال اول (اجرای سریع) |
| `--judge-model M` | مدل داور جدا (توصیه: برای بی‌طرفی، مدلی غیر از مدل خودِ اپ) |
| `--min-accuracy 80` | اگر دقت < ۸۰٪ شد، exit code غیرصفر (برای CI) |

خروجی: گزارش خوانا در ترمینال + فایل کامل JSON در `eval/reports/`.

## معنی معیارها

- **دقت (accuracy)**: میانگین نمره‌ی ۰/۱/۲ نسبت به `must_include` هر سؤال.
- **توهم (hallucination)**: فقط وقتی ادعای *غلط* یا مشخصات *جعلی* (مدل/قیمت/استاندارد ساختگی)
  یا موردی از `must_not_include` بیاید. نبودِ منبع به‌تنهایی توهم **نیست**.
- **grounded**: ادعاها با منبع بازیابی‌شده یا با معیارها سازگارند.
- **بدون بازیابی سند**: پاسخ از دانش مدل آمده نه از knowledge base (لزوماً بد نیست).
- **تطابق intent**: آیا دسته‌بندی سؤال با `expected_intent` خواند.

## ⚠ درباره‌ی دقت — مهم

تا وقتی یک **کارشناس دامنه** فیلدهای `must_include`/`must_not_include`/`criteria` یک سؤال را
بازبینی و `verified: true` نکرده، نمره‌ی آن سؤال «آزمایشی» است و در گزارش جدا علامت می‌خورد.
دلیل: یک معیار مرجعِ *غلط* بدتر از نبود ارزیابی است — پاسخ درست را جریمه می‌کند.

بنابراین گردش کار درست:
1. سؤال‌های `verified:false` را با دانش فنی خودت مرور کن، معیارها را اصلاح یا تأیید کن، `verified:true` بگذار.
2. سؤال‌های واقعیِ پرتکرارِ مشتری‌ها را هم اضافه کن (هرچه به سؤال‌های واقعی نزدیک‌تر، ارزیابی معنادارتر).

## نکته‌ی بی‌طرفی داور

داور پیش‌فرض همان مدل اپ (`gpt-5.4`) است؛ ممکن است کمی به خودش ارفاق کند. برای ارزیابی
دقیق‌تر، با `--judge-model` یا متغیر `EVAL_JUDGE_MODEL` یک مدل متفاوت به‌عنوان داور بگذار.
